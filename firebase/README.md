# قواعد Firebase لتطبيق YS.JOB

ملف [`firestore.rules`](./firestore.rules) هو نسخة قواعد Firestore المراجعة لتطبيق YS.JOB. لا يُنشر الملف تلقائيًا من المشروع؛ يجب نسخه يدويًا إلى **Firebase Console → Firestore Database → Rules** ثم الضغط على **Publish**.

ملف [`storage.rules`](./storage.rules) هو نسخة قواعد Firebase Storage المطلوبة لرفع الشعار والصورة الشخصية والسيرة الذاتية. يجب نسخه يدويًا إلى **Firebase Console → Storage → Rules** ثم الضغط على **Publish**. لا يمنح الملف الوصول إلا لمالك مجلده ضمن `photos/{uid}` و`logos/{uid}` و`resumes/{uid}`، ويتحقق من أنواع الملفات وأحجامها.

> تعتمد القواعد على مستند مستخدم موجود في `users/{uid}` ويحتوي على `role` و`isActive`. يجب إنشاء أول حساب إداري بطريقة موثوقة من Firebase Console أو بيئة إدارية خاضعة للرقابة، وليس من واجهة التسجيل العامة.

تتطلب قاعدة `notifications` الحقل الداخلي `applicationId`، لأن التطبيق ينفّذ تحديث حالة الطلب وإنشاء الإشعار داخل Batch واحد. بهذه العلاقة تتحقق القواعد من أن صاحب الشركة يرسل إشعارًا للباحث صاحب الطلب فقط، وبعد تغيّر حالة ذلك الطلب.

عند اعتماد المشرف لطلب تمييز، ينفذ التطبيق `WriteBatch` واحدًا يحدّث حالة
`feature_requests` إلى `approved`، ويضبط `jobs.isFeatured` إلى `true`، وينشئ
إشعارًا لصاحب العمل. تسمح القواعد الحالية بهذا الإشعار لأن إنشاؤه مقتصر على
المشرف النشط وفق `isAdmin()`.

تسمح قاعدة `users` للمالك النشط بتحديث حقول ملفه المهنية فقط، وتشمل حقول
الهاتف والصورة ومجال الشركة واسمها والمسمى الوظيفي. يظل الدور وحالة الحساب
ومعرف المستخدم وتاريخ الإنشاء محمية من أي تعديل ذاتي.
