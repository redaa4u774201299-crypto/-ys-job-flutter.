# تقرير اختبار Flutter Web — YS JOB

**تاريخ الاختبار:** 20 أغسطس 2026  
**نطاق الاختبار:** بناء الإنتاج الحالي لتطبيق Flutter Web، مع عدم إنشاء بيانات تجريبية أو تعديل بيانات Firestore القائمة.

## ملخص النتيجة

تم التحقق من سلامة البناء الآلي وتحميل الواجهة الإنتاجية والتنقل عبر المسارات العامة وحالات الحماية غير المصرح بها. لم تظهر أخطاء تشغيل في سجل المتصفح خلال مسارات الاختبار. يتطلب اختبار التدفقات التي تكتب إلى Firestore، ومنها تحديث الملف الشخصي ونافذة قص الصورة، تسجيل دخول بحساب حقيقي وموافقة صريحة من مالك الحساب قبل تنفيذ أي حفظ.

| فئة التحقق | النتيجة | ملاحظات |
|---|---|---|
| التحليل الساكن | ناجح | لا توجد ملاحظات تحليلية بعد دمج القص. |
| اختبارات Flutter | ناجحة | نجح 43 اختبارًا، وتشمل اختبارات ضغط Base64 والصور المصغرة وإلغاء القص. |
| بناء Flutter Web | ناجح | تم بناء نسخة الإنتاج باستخدام `flutter build web --no-tree-shake-icons`. |
| السجل البرمجي للمتصفح | ناجح | لم يظهر خطأ JavaScript أو Firebase في جلسة الفحص. |
| واجهات المصادقة | ناجحة | ظهرت صفحات تسجيل الدخول وإنشاء الحساب باللغة العربية وبتخطيط RTL. |
| الواجهات العامة | ناجحة | ظهرت الصفحة الرئيسية وقائمة الوظائف وصفحة الشركات، مع حالات فارغة حقيقية عند غياب البيانات. |
| المسارات المحمية | ناجحة | لم تُعرض بيانات الملف الشخصي أو لوحة الباحث أو لوحة الشركة أو لوحة الإدارة دون جلسة مستخدم مصرح لها. |
| توافق المسار القديم | ناجح | أعاد `/employer/post-job` التوجيه إلى `/add-job` مع استمرار حماية محتوى صاحب العمل. |
| وظيفة غير متاحة | ناجح | أظهر المسار غير الموجود حالة واضحة بدل شاشة فارغة أو خطأ تشغيل. |

## المسارات التي تم التحقق منها

| المسار | الحالة المرصودة |
|---|---|
| `/` | الصفحة الرئيسية تظهر باللغة العربية وتعرض حالة خالية حقيقية عند غياب الوظائف. |
| `/login` | نموذج تسجيل الدخول يظهر بصورة سليمة. |
| `/register` | نموذج إنشاء الحساب يظهر مع أدوار الباحث وصاحب العمل فقط. |
| `/jobs` | البحث والتصفية يظهران، وتظهر حالة عدم وجود نتائج بطريقة سليمة. |
| `/companies` | تظهر حالة انتظار بيانات الشركات دون إنشاء شركات تجريبية. |
| `/profile` | يطلب تسجيل الدخول، ولا يعرض بيانات حساب. |
| `/seeker-dashboard` | يطلب تسجيل الدخول ولا يعرض طلبات باحث. |
| `/employer-dashboard` | يطلب تسجيل دخول صاحب شركة ولا يعرض أدوات الشركة. |
| `/admin-dashboard` | يظهر وصول مقيّد ولا يعرض أدوات المدير. |
| `/employer/post-job` | يعيد التوجيه إلى `/add-job` مع حماية الوصول. |
| `/job-details/non-existent` | يعرض رسالة أن الوظيفة غير متاحة حاليًا. |

## عناصر معلّقة على جلسة مستخدم حقيقية

لا يمكن إكمال البنود التالية دون تسجيل دخول حساب صالح؛ إذ إن اختبارها يتضمن قراءة أو كتابة بيانات الحساب وFirestore:

1. الدخول الفعلي حسب الدور، ثم إعادة التوجيه إلى لوحة الباحث أو صاحب العمل أو المدير.
2. تعديل الملف الشخصي للباحث أو الشركة، بما في ذلك اختيار صورة، فتح نافذة القص، التأكيد أو الإلغاء، والحفظ إلى Firestore.
3. استعراض الوظائف التي يملكها صاحب العمل، إنشاء وظيفة، وإدارة طلباتها.
4. تقديم الباحث على وظيفة حقيقية ومتابعة تغير حالة الطلب والإشعارات.
5. إدارة المدير للمستخدمين والوظائف وطلبات التمييز وفق الصلاحية الحقيقية.

> لم تُنشأ بيانات وهمية ولم يُنفّذ أي حفظ أو تعديل في Firestore ضمن هذا الاختبار.

## الخطوة المقترحة

بعد تسجيل الدخول يدويًا في جلسة المتصفح بحساب تجريبي حقيقي أو حساب يصرّح مالكه باستخدامه، يمكن إكمال اختبار الملف الشخصي وميزة قص الصور بالبيانات الفعلية. يجب تجنب الضغط على زر الحفظ في أي تدفق إلا بعد موافقة صريحة إذا كان الحساب أو البيانات إنتاجية.
