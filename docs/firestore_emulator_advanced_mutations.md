# اختبارات الحذف والتحديثات المركبة عبر Firestore Emulator

هذا الملحق يوسّع حارس قواعد Firestore في منصة **YS JOB** بحيث يتحقق من الحذف والتحديثات الجزئية وذرية الدفعات، دون الاتصال بمشروع `ysjob-web` أو بياناته الحقيقية.

## مبدأ الاختبار

لا يكفي اختبار إنشاء وثيقة الدليل العام. يجب أن يبقى كل من التحديث والحذف مقيدين بالمالك وبنية الوثيقة العامة؛ فالتحقق من `request.resource.data` في التحديث يحكم الحالة النهائية للوثيقة بعد دمج الحقول الجزئية، بينما تتحقق قاعدة الحذف من هوية المنفذ فقط. [1]

| الحالة | النتيجة المتوقعة | الحماية التي تثبتها |
| --- | --- | --- |
| حذف المالك لوثيقة `company_directory/{uid}` | نجاح | تمكين إزالة الدليل العام لصاحبه عند الحاجة. |
| حذف مستخدم آخر للوثيقة | رفض | منع الحذف عبر تجاوز الملكية. |
| تحديث الاسم أو الوصف فقط | نجاح | دعم `updateDoc` مع استمرار التحقق من البنية الكاملة. |
| تغيير `id` إلى مالك آخر | رفض | منع تحويل الوثيقة إلى هوية شركة أخرى. |
| دفعة تعدل `users` وتضيف `phone` إلى الدليل | رفض كامل | منع تسريب هاتف إلى مجموعة عامة ومنع حفظ أي جزء من الدفعة. |

## أمر التشغيل

نفّذ الأوامر من جذر المشروع:

```bash
npm ci
npm run test:firestore-rules
```

يشغّل الأمر المحاكي بمشروع `demo-ysjob` ويزيل بيانات الاختبار بعد التنفيذ. لا تضف بيانات حسابات حقيقية أو مفاتيح Firebase إلى الاختبارات أو ملفات تهيئة المحاكي.

## إضافة حالة جديدة

أضف كل حالة إلى `test/firestore_rules/company_directory.rules.test.mjs` واتبع التسلسل نفسه: ازرع الحالة بـ`withSecurityRulesDisabled`، ثم نفّذ العملية من `authenticatedContext` أو `unauthenticatedContext`، ثم استخدم `assertSucceeds` أو `assertFails`، وأخيرًا تحقق من الحالة الفعلية بامتيازات إدارية. اختبر دائمًا بقاء المستندات دون تغير عندما تفشل الدفعة.

> لا تجعل الاختبار يمر بتخفيف القاعدة. إذا كان سلوك المنتج صحيحًا لكنه مرفوض، عدّل القاعدة والاختبار معًا بعد مراجعة أثر ذلك على الملكية والبيانات العامة.
