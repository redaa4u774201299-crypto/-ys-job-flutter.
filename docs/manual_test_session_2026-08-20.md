# جلسة التحقق اليدوي من Firebase والمصادقة

**التاريخ:** 2026-08-20  
**البيئة:** Flutter Web محليًا على Chromium عبر `http://localhost:8080`

## الملاحظة الأولى

عند فتح التطبيق في متصفح الاختبار ظهرت صفحة بيضاء بعد تحميل Flutter، ولم تظهر عناصر تفاعلية خلال اللقطة الأولى. لم تتضمن وحدة التحكم حتى هذه اللحظة أخطاء JavaScript أو Firebase؛ سجلت فقط تحميل DDC وبدء `main`.

## تحقق القراءة العامة

اكتمل تحميل الصفحة الرئيسية لاحقًا بصورة طبيعية، وظهرت رسالة الحالة الصادقة «لا توجد وظائف منشورة حاليًا» في قسم أحدث الوظائف. فُتح مسار `/jobs` للتحقق من صفحة القائمة بعد اكتمال تحميلها.

ظهرت صفحة `/jobs` بنجاح برسالة «لا توجد وظائف تطابق معايير البحث الحالية»، بما يتفق مع عدم توفر نتائج ظاهرة. سجلت وحدة تحكم المتصفح تحميل Flutter وبدء التطبيق فقط، من دون أخطاء Firebase أو Firestore أو رفض صلاحيات حتى هذه النقطة.

لم تُظهر قائمة موارد Performance أي عنوان يتضمن `firestore` أو `firebase` أو `googleapis`. هذه الملاحظة ليست دليلاً قاطعًا على غياب الاتصال، إذ قد تستخدم مكتبة Firestore قناة شبكة لا تظهر ضمن مورد تقليدي أو تكون الموارد مخزنة مؤقتًا.

اكتمل تحميل دليل الشركات في `/companies` وأظهر حالة فراغ أو تعذر تحميل صادقة، من دون خطأ ظاهر في وحدة التحكم. غير أن تحقق الكتابة والمصادقة الناجحة ما زال يتطلب حساب اختبار مصرحًا به.

## جاهزية اختبار المصادقة

فُتحت شاشة `/login` واكتمل تحميلها؛ تحتوي حقلي البريد الإلكتروني وكلمة المرور ورابط إنشاء حساب وخيار تسجيل Google. لا تعرض الواجهة في النسخة الحالية رابطًا لاستعادة كلمة المرور.

تُرسم حقول Flutter Web في هذه الجلسة كواجهة Canvas من دون عناصر إدخال قابلة للاستهداف عبر متصفح الأتمتة؛ لم تُطبَّق محاولة إدخال البريد ولم تُرسل أي بيانات أو طلب مصادقة. يلزم استخدام جلسة Chromium التفاعلية التي بدأها Flutter، أو اختبار موجّه داخل التطبيق، لإكمال تدفقات تسجيل الدخول والتسجيل واستعادة كلمة المرور.

## تحقق Firestore المباشر دون مصادقة

أعاد مسار REST الرسمي لمجموعة `jobs` حالة HTTP 200 بجسم فارغ، وهو متسق مع عدم وجود مستندات ظاهرة للقراءة العامة في هذه اللحظة. أما الاستعلام عن مجموعة `users` فأعاد HTTP 403 مع `PERMISSION_DENIED`. لذلك لا يمكن لدليل الشركات العام أن يقرأ مستندات المستخدمين من متصفح غير مسجّل بموجب القواعد الحالية. هذه نتيجة أمنية متوقعة إن كانت وثائق المستخدمين خاصة، لكنها تكشف تعارضًا وظيفيًا مع اعتماد صفحة الشركات العامة على مجموعة `users`؛ يلزم فصل ملفات الشركات العامة في مجموعة آمنة للعرض أو توفير مسار قراءة محكوم، ولا يجوز تخفيف قواعد ملفات المستخدمين الخاصة بلا مراجعة أمنية.

## فحص رابط المعاينة الخارجي

استمرت عملية Flutter في الاستماع على المنفذ `8080`، لكن المسار الجذري `/` أعاد HTTP 404، بينما أعاد `/index.html` حالة HTTP 200. استجاب الرابط الخارجي الممرر عبر الوكيل عند إضافة معلمة استعلام، إلا أن التطبيق ظهر كمساحة Flutter فارغة ولم تسجل وحدة التحكم أي خطأ. لذلك لا يصلح خادم التطوير المؤقت هذا كرابط QA خارجي موثوق، وتلزم خدمة نسخة Web مبنية عبر خادم HTTP تقليدي قبل متابعة الاختبار الخارجي.

## اختبار إنشاء الحساب — قيد التحقق

فُعّلت طبقة الدلالات في Flutter Web، ثم عُبّئت حقول نموذج التسجيل عبر عناصر الإدخال الفعلية وأُرسل نموذج باحث عن عمل مخصص لاختبار الجودة بعد تفويض المستخدم. اكتمل التسجيل بنجاح وانتقل التطبيق تلقائيًا إلى `/seeker-dashboard`، حيث ظهرت رسالة ترحيب باسم الحساب وإحصاءات الطلبات الفارغة. يثبت ذلك نجاح إنشاء هوية Firebase ومسار التوجيه بحسب دور الباحث؛ ما زال التحقق من عدم وجود خطأ Firestore في وحدة التحكم وتدفق تسجيل الدخول المنفصل مطلوبين.

## سجل وحدة التحكم بعد التسجيل

لا يحتوي سجل وحدة التحكم المتاح بعد التسجيل على أخطاء Firebase Authentication أو Firestore. السجل الظاهر يتضمن أوامر فحص واجهة الاختبار السابقة فقط، مع خطأ JavaScript تركيبي من محاولة أولى لتفعيل طبقة الدلالات (`Unexpected token ';'`)؛ نجحت المحاولة التالية ولم يكن الخطأ صادرًا عن التطبيق أو Firebase.

## اختبار تسجيل الدخول — قيد التنفيذ

فُتحت شاشة `/login` من شريط التنقل، ثم أُدخل بريد حساب الجودة وكلمة مروره في عناصر الإدخال الفعلية. لم يُرسل نموذج الدخول بعد وقت تدوين هذه الملاحظة؛ ستسجل النتيجة بعد استجابة Firebase والتحقق من المسار التالي.

أظهر إرسال أولي أن التعبئة المجمعة لعناصر DOM لا تُحدّث حالة نموذج Flutter؛ أعاد التطبيق رسائل التحقق المحلية عن البريد وكلمة المرور المطلوبين، ولم يصل أي طلب مصادقة إلى Firebase في تلك المحاولة. أعيدت تعبئة الحقول عبر أحداث إدخال منفصلة لاستكمال الاختبار الصحيح.

نجح تسجيل الدخول المنفصل بعد إدخال الحقول عبر أحداث منفصلة. أعادت Firebase Authentication الجلسة بنجاح، ووصل التطبيق إلى `/seeker-dashboard` مع عرض اسم حساب الجودة وحالة طلبات فارغة؛ وهذا يؤكد أيضًا قراءة وثيقة المستخدم المرتبطة بالجلسة من Firestore.
